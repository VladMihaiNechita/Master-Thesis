IRC GENERATOR EXPERIMENTS
=========================

Recorded: 2026-07-27

This file archives the 14 IRC generator experiments: the original IRC
implementation and IRC1 through IRC13. It is intended to preserve the
experimental history after the individual variant files are removed.


1. EXPERIMENTAL CONTEXT
=======================

Unless stated otherwise, the experiments used:

- ViT-Tiny trained as a Masked Autoencoder (MAE).
- 224 x 224 RGB images.
- 75% training mask ratio.
- norm_pix_loss = false.
- Training batch size 4,000.
- 100 million generated training images.
- A checkpoint every 4 million images.
- The same pretraining and evaluation procedure for every generator.
- One run per generator. Small differences should therefore not be interpreted
  as statistically significant without additional seeds.

The reported accuracy is the unweighted mean over nine validation datasets.

Real datasets:

- CIFAR-10
- DTD
- EuroSAT
- Food-101
- Oxford-IIIT Pets
- Tiny ImageNet-200

Synthetic datasets:

- Line Field Orientation
- Shape-Color Objects
- Texture Mosaic

"Real mean" is the mean of the six real datasets. "Synthetic mean" is the mean
of the three synthetic datasets. "Reconstruction" is the mean MAE validation
reconstruction loss; lower is better.

W&B project:
https://wandb.ai/vladmihainechita2002-vrije-universiteit-amsterdam/universal-pretraining-for-images


2. COMMON ORIGINAL IRC IMPLEMENTATION
=====================================

The following behavior is inherited by the variants unless a section explicitly
states otherwise.

Image buffer:

- The CPU buffer contains 20,000 uint8 images.
- Initial contents are 10,000 independent-pixel RGB noise images and 10,000
  random solid RGB images.
- Each call to generate() resets 0.75% of the buffer: 150 random positions.
- Of those 150 reset positions, 75 receive fresh pixel noise and 75 receive
  fresh solid colors.

Buffer evolution per generate() call:

- Select 1,000 update/source positions with torch.randperm().
- Independently select 1,000 partner positions with torch.randperm().
- Each list has no duplicate positions internally, but the two lists can
  overlap and an image can be paired with itself.
- The selected source images are also the positions overwritten by the result.
- Process the 1,000 pairs in chunks of 200.
- Transfer uint8 images to the GPU first, then convert them to float in [0, 1].
- Run one sampled spatial program and one freshly initialized residual random
  CNN over all five chunks. Per-image spatial randomness is fresh per chunk.
- Convert the results back to uint8 and write them into the 1,000 source/update
  positions.
- Return a random, non-repeating-within-the-batch sample from the full buffer.

Fresh inputs inside the spatial program:

- Before applying spatial operations, every selected source image independently
  has a 5% probability of being replaced.
- A replaced source has a 50% probability of becoming independent-pixel noise
  and a 50% probability of becoming a solid random RGB color.
- This is an expected 50 replacements among the 1,000 selected sources, not an
  exactly fixed count.

Original random spatial program:

- Program length is sampled by adding an operation and then stopping with 50%
  probability.
- The maximum length is 100, but the expected length is 2.
- One program is sampled per generate() call and reused over all five chunks.
- Each instruction is uniformly sampled from six operations:
    1. crop and resize
    2. blur
    3. pool and resize
    4. roll
    5. flip
    6. crossover

Operation details:

- Crop/resize selects an independent 50%-90% crop per image, with a random
  valid translation, and restores it using bilinear grid sampling.
- Blur uses reflect padding followed by stride-1 average pooling. The kernel is
  sampled once per program instruction from 3, 5, or 9.
- Pool/resize downsamples using average pooling with factor 2, 4, or 8 and
  restores the original size with bilinear interpolation.
- Roll shifts by +/-12.5% or +/-25% independently along each image dimension.
- Flip chooses either the horizontal or vertical dimension.
- The original crossover uses an independently sampled 7 x 7 binary mask,
  enlarged with nearest-neighbor interpolation.

Residual random convolution:

- A new CNN is initialized on every generate() call and shared across its five
  chunks.
- Architecture: Conv(3 -> 16, 3 x 3), LeakyReLU(0.2),
  Conv(16 -> 3, 3 x 3).
- The CNN predicts a residual instead of a completely new image:

      output = clamp(image + 0.1 * tanh(CNN(image - 0.5)), 0, 1)

4. INDIVIDUAL EXPERIMENTS
=========================

EXPERIMENT 1 - IRC
File: irc.py
W&B run: 1ti8zvrl

Implementation:

- This is the original implementation described in Section 2.
- All six spatial operations modify the image.
- Crossover uses an independent 7 x 7 binary block mask.
- Output batches are sampled randomly from the buffer.

Results:

- Final at 100M: 51.5637%.
- Best: 51.8932% at 80M.
- Real mean: 39.9041%.
- Synthetic mean: 74.8828%.
- Reconstruction: 0.01736935.

Observation:

- This established the first working IRC baseline.
- Its main weakness was the small disconnected crossover mask. Replacing this
  mask with connected multiscale regions produced the largest successful
  improvement in the entire ablation series.


EXPERIMENT 2 - IRC1
File: irc1.py
W&B run: ytu1f23y

Difference from IRC:

- Only the sampling of the returned training batch changed.
- IRC samples every output batch independently with torch.randperm().
- IRC1 creates a shuffled order over all 20,000 buffer positions and consumes
  it without repetition across calls. It reshuffles only after a complete pass.
- Update/source and partner sampling remained unchanged and random.

Results:

- Run stopped at 32M.
- Best: 51.2679% at 20M.
- Final at 32M: 50.7476%.
- IRC at the matched checkpoints was 50.8017% at 20M and 50.9474% at 32M.

Observation:

- Non-repeating output sampling did not meaningfully improve representation
  quality.
- The small +0.47 point difference at 20M disappeared by 32M, where IRC1 was
  0.20 points below IRC.
- Random output sampling was therefore retained in later variants.


EXPERIMENT 3 - IRC2
File: irc2.py
W&B run: cdq7o5ia

Difference from IRC:

- Only crossover geometry changed.
- For every crossover instruction, choose a field resolution of 2, 4, or 8.
- Sample a low-resolution continuous random field.
- Enlarge it to image resolution with bicubic interpolation.
- Independently sample a threshold in [0.35, 0.65] for each image.
- Pixels above and below the threshold select connected regions from the two
  partner images.
- The other five operations and the random CNN remained active.

Results:

- Final at 100M: 55.7247%.
- Best: 55.8028% at 96M.
- Improvement over IRC at 100M: +4.1610 points.
- Real mean improved from 39.9041% to 42.8205%.
- Synthetic mean improved from 74.8828% to 81.5331%.
- Reconstruction improved from 0.01736935 to 0.01496600.

Observation:

- Connected-region crossover was the most important successful generator
  modification.
- It preserved larger coherent regions and greatly improved both real and
  synthetic transfer.


EXPERIMENT 4 - IRC3
File: irc3.py
W&B run: wxfecpbe

Difference from IRC2:

- The residual random CNN output was not applied.
- The CNN was still constructed so its initialization consumed the same random
  draws as IRC2.
- Everything else, including connected crossover, remained unchanged.

Results:

- Run stopped at 60M.
- Final/best at 60M: 54.2477%.
- IRC2 at the matched 60M checkpoint: 54.7836%.
- Removing the CNN cost 0.5359 points at 60M.

Observation:

- The CNN provides a modest but consistent benefit rather than explaining the
  majority of IRC2's performance.
- The spatial program, especially connected crossover, remains the dominant
  component.
- The CNN should remain in the selected generator.


EXPERIMENT 5 - IRC4
File: irc4.py
W&B run: weesorok

Difference from IRC2:

- Connected crossover was disabled.
- Crossover instructions were still executed and consumed their random draws,
  but their result was discarded and the previous image was restored.
- Crop/resize, blur, pool/resize, roll, flip, and the CNN remained active.

Results:

- Run stopped at 72M.
- Initial 0M result: 29.4952%.
- Result at 20M: 22.7040%.
- Final at 72M: 27.0489%.
- IRC2 at the matched 72M checkpoint: 55.2699%.

Observation:

- Removing crossover was catastrophic; performance fell below the untrained
  0M result.
- Repeated non-crossover transformations and CNN mutations do not maintain a
  useful buffer distribution by themselves.
- Crossover is essential, not merely one optional augmentation.


EXPERIMENT 6 - IRC5
File: irc5.py
W&B run: r8jcw0sr

Difference from IRC2:

- Only connected-crossover results were retained.
- The program still sampled all six original instruction types.
- Crop/resize, blur, pool/resize, roll, and flip were executed but their results
  were discarded.
- Therefore, crossover occurred with probability 1/6 per instruction.
- The fresh-source mechanism and random CNN remained active.

Results:

- Final at 100M: 54.0475%.
- Best: 54.0915% at 92M.
- Difference from IRC2 at 100M: -1.6772 points.

Observation:

- Occasional connected crossover plus the CNN is already a strong generator.
- However, crossover alone did not reach IRC2, indicating that at least some
  additional spatial operations are useful.


EXPERIMENT 7 - IRC6
File: irc6.py
W&B run: cg7gjgfr

Difference from IRC5:

- Connected crossover and crop/resize results were retained.
- Each has probability 1/6 per sampled instruction.
- Blur, pool/resize, roll, and flip results were discarded.
- The random CNN remained active.

Results:

- Final at 100M: 55.8189%.
- Best: 56.0430% at 92M.
- Improvement over IRC5 at 100M: +1.7714 points.
- It slightly exceeded IRC2 despite using fewer active spatial operations.

Observation:

- Crop/resize adds substantial complementary variation to connected crossover.
- The result also suggested that some of IRC2's other operations were neutral
  or harmful.


EXPERIMENT 8 - IRC7
File: irc7.py
W&B run: 9jxh1hsv

Difference from IRC2:

- The program's operation list contains only connected crossover.
- Program length is unchanged: at least one crossover, a 50% stopping chance
  after every instruction, and an expected length of two.
- Unlike IRC5, every instruction is an active crossover.
- The random CNN remained active.

Results:

- Best: 51.6181% at 48M.
- 60M: 50.5071%.
- 68M: 44.8135%.
- 72M: 43.4583%.
- Final at 100M: 35.3094%.

Observation:

- The run collapsed after approximately 48M even though training continued.
- Connected crossover is essential at a low rate, but repeated mandatory
  crossover destroys useful structural diversity over long buffer evolution.
- The crossover probability and mutation-depth distribution matter as much as
  the crossover implementation.


EXPERIMENT 9 - IRC8
File: irc8.py
W&B run: dp7c9tp1

Difference from IRC6:

- Blur results were added to connected crossover and crop/resize.
- Connected crossover, crop/resize, and blur each have probability 1/6 per
  instruction.
- Pool/resize, roll, and flip instructions are still sampled and executed, but
  their results are discarded.
- Consequently, every instruction has:
    - 1/6 connected crossover
    - 1/6 crop/resize
    - 1/6 blur
    - 1/2 effective no-op
- The random CNN remains active for every generate() call.

Effective mutation-depth distribution:

- The spatial program still has an expected two instructions.
- Expected active spatial operations per program: 1.
- Probability of zero active spatial operations: 1/3.
- Probability of exactly one active spatial operation: 4/9.
- Probability of two or more active spatial operations: 2/9.
- Fresh-source replacement and the CNN still run when the spatial program has
  zero active operations.

Results:

- Final at 100M: 57.2437%.
- Best: 57.2468% at 92M.
- Improvement over IRC6 at 100M: +1.4248 points.
- Real mean: 43.4556%.
- Synthetic mean: 84.8198%.
- Reconstruction: 0.01464956.

Observation:

- Blur adds useful local-scale variation on top of crossover and crop/resize.
- IRC8 achieved the best overall result of all 14 experiments.
- Its benefit is not just the set of active operations. The stochastic mixture
  of zero, one, and multiple active spatial operations is also important.
- This is the selected generator for the clean retained implementation.


EXPERIMENT 10 - IRC9
File: irc9.py
W&B run: kg9cfmp3

Difference from IRC8:

- Pool/resize results were also retained.
- Connected crossover, crop/resize, blur, and pool/resize each have probability
  1/6 per instruction.
- Roll and flip remain effective no-ops.
- The random CNN remained active.

Results:

- Final at 100M: 56.7986%.
- Best: 56.9964% at 92M.
- Difference from IRC8 at 100M: -0.4451 points.
- Real mean decreased by 0.6477 points.
- Synthetic mean was almost unchanged: -0.0400 points.
- Reconstruction worsened from 0.01464956 to 0.01516792.

Observation:

- Pool/resize did not improve the generator.
- Its small overall cost came almost entirely from the real datasets.
- Pool/resize should not be included in the selected implementation.


EXPERIMENT 11 - IRC10
File: irc10.py
W&B run: 1tal3mc0

Difference from IRC8:

- The instruction list was changed to contain only connected crossover,
  crop/resize, and blur.
- Every sampled instruction therefore modifies the image.
- Each active operation has probability 1/3.
- Program length remains geometrically distributed with mean 2.
- Expected active operations increased from 1 in IRC8 to 2.
- There are no effective no-op instructions.

Results:

- Final at 100M: 55.9660%.
- Best: 55.9676% at 92M.
- Difference from IRC8 at 100M: -1.2777 points.
- Real mean was 0.1785 points higher than IRC8.
- Synthetic mean was 4.1900 points lower than IRC8.
- IRC10 learned faster early but was overtaken during later training.

Observation:

- Always applying an operation made the buffer evolve too aggressively.
- The damage was concentrated on synthetic structural tasks.
- IRC8's effective no-op probability acts as mutation-rate control and should
  not simply be removed.


EXPERIMENT 12 - IRC11
File: irc11.py
W&B run: lql37hiq

Difference from IRC9:

- The instruction list contains only connected crossover, crop/resize, blur,
  and pool/resize.
- Every instruction is active and each operation has probability 1/4.
- Program length remains geometrically distributed with mean 2.
- Roll, flip, and all effective no-op instructions were removed.

Results:

- Final at 100M: 56.3416%.
- Best: 56.3470% at 84M.
- Difference from IRC9 at 100M: -0.4570 points.
- Real mean improved by 0.4563 points.
- Synthetic mean decreased by 2.2833 points.

Observation:

- Removing no-op instructions again hurt the overall result, especially on the
  synthetic datasets.
- Adding pool/resize did not solve the excessive-mutation problem seen in
  IRC10.


EXPERIMENT 13 - IRC12
File: irc12.py
W&B run: gqwbopul

Difference from IRC8:

- The spatial program and CNN are exactly the IRC8 design.
- The source mixture changed from 50% colors / 50% pixel noise to
  75% colors / 25% pixel noise in all three places:
    1. initial buffer construction
    2. the 0.75% buffer reset
    3. the 5% fresh-source replacement inside the spatial program

Results:

- Final at 100M: 56.8077%.
- Best: 56.8490% at 80M.
- Difference from IRC8 at 100M: -0.4360 points.
- Real mean improved by 0.2261 points.
- Synthetic mean decreased by 1.7600 points.
- IRC12 was stronger early in training but IRC8 became stronger later.

Observation:

- More solid-color sources make the early distribution easier to organize and
  provide a small real-dataset benefit.
- Retaining more pixel noise is better for long-term synthetic diversity and
  the overall nine-dataset mean.
- The original 50/50 source mixture remains the best static choice.
- A 75/25-to-50/50 training schedule is a possible future experiment, but it
  has not been tested.


EXPERIMENT 14 - IRC13
File: irc13.py
W&B run: xcg939hy

Difference from IRC8:

- Every program contains exactly one spatial instruction.
- The one instruction is uniformly selected from connected crossover,
  crop/resize, and blur.
- Each operation therefore has probability 1/3.
- There are no zero-operation programs and no multi-operation programs.
- The expected number of active operations remains 1, matching IRC8's expected
  count, but the mutation-depth distribution is different.
- Fresh-source replacement and the random CNN remain unchanged.

Results:

- Final at 100M: 55.6324%.
- Best: 55.8158% at 92M.
- Difference from IRC8 at 100M: -1.6113 points.
- Real mean decreased by 0.5069 points.
- Synthetic mean decreased by 3.8200 points.
- Shape-Color Objects decreased by 6.88 points.
- Texture Mosaic decreased by 4.34 points.

Observation:

- Matching only IRC8's expected number of active operations is insufficient.
- The mixture of zero-operation, one-operation, and multi-operation programs
  is better than forcing exactly one operation.
- This result confirms that IRC8's variable mutation depth is useful rather
  than accidental.

Evaluation note:

- The 8M and 72M-100M evaluations contain all nine datasets.
- Several 12M-68M DAS-6 JSON files contain only the first 6-8 datasets because
  their 15-minute evaluation jobs timed out. Their partial means should not be
  used as points on the full nine-dataset learning curve.


5. MAIN CONCLUSIONS
===================

1. IRC8 is the best tested generator by overall validation accuracy.

2. Connected-region crossover is essential.
   - IRC -> IRC2: +4.1610 points.
   - Removing crossover in IRC4 caused catastrophic degradation.

3. Connected crossover must be applied at a controlled rate.
   - Occasional crossover is strong.
   - Mandatory repeated crossover in IRC7 eventually collapsed the buffer.

4. Crop/resize and blur are both useful.
   - IRC5 -> IRC6, adding crop/resize: +1.7714 points.
   - IRC6 -> IRC8, adding blur: +1.4248 points.

5. Pool/resize should be excluded.
   - IRC8 -> IRC9: -0.4451 points.

6. The random residual CNN should remain.
   - Removing it cost 0.5359 points at the matched 60M checkpoint.

7. Mutation-depth variability matters.
   - IRC10 applied approximately two active operations per program and was too
     aggressive.
   - IRC13 applied exactly one operation and was also worse.
   - IRC8's distribution over zero, one, and multiple active operations was
     best.

8. A 50/50 solid-color/pixel-noise source mixture remains best overall.
   - A 75/25 mixture learned faster early and slightly favored real datasets,
     but reduced final synthetic performance.

9. Shuffled non-repeating output sampling did not help.


6. SPECIFICATION FOR A CLEAN RETAINED IRC8 IMPLEMENTATION
=========================================================

The clean retained generator should preserve:

- A 20,000-image uint8 CPU buffer.
- Initial buffer: 50% independent-pixel noise, 50% solid random RGB colors.
- Reset 0.75% of buffer positions per generate() call with a 50/50 source mix.
- Randomly select 1,000 source/update images and 1,000 partner images.
- Process them in chunks of 200, converting to float after GPU transfer.
- Independently replace approximately 5% of selected sources with a 50/50 mix
  of fresh noise and fresh colors.
- Connected-region crossover using:
    - random field resolution 2, 4, or 8
    - bicubic field enlargement
    - independent threshold in [0.35, 0.65] per image
- Crop/resize and blur exactly as in the original implementation.
- A geometric program length with a 50% stopping probability and expected
  length 2.
- Per instruction probabilities:
    - connected crossover: 1/6
    - crop/resize: 1/6
    - blur: 1/6
    - effective no-op: 1/2
- A freshly initialized 3 -> 16 -> 3 residual random CNN per generate() call.
- output = clamp(image + 0.1 * tanh(change), 0, 1).
- Write results back into the selected source/update positions.
- Random output sampling from the complete buffer.

Important reproducibility detail:

- The historical IRC8 code obtains the 1/2 effective no-op probability by
  sampling pool/resize, roll, or flip, executing the operation, and then
  restoring the previous image. This preserves the random-number consumption
  of the inherited IRC2 program.
- A clean implementation may instead sample an explicit identity operation
  with probability 1/2. This preserves the intended probability distribution
  but will not produce bit-for-bit identical buffers for the same global seed,
  because the sequence of consumed random numbers changes.
- Keep the execute-and-restore behavior only if exact historical seeded
  reproducibility is required. Otherwise, an explicit identity operation is
  simpler and avoids unnecessary computation.


7. SELECTED GENERATOR
=====================

Selected version: IRC8

Reason:

- Highest final and best overall validation accuracy.
- Strongest synthetic mean.
- Good real-dataset transfer.
- Stable through 100M images.
- Every major component is supported by a direct ablation:
  connected crossover, crop/resize, blur, controlled mutation depth, source
  mixture, and residual random CNN.
